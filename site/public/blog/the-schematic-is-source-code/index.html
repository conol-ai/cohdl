The schematic is source code

Software earned version control, code review, type checkers and CI. Schematics are still drawings, and their mistakes are still found at the assembly house. CoHDL is my answer: treat the board as a program, and give it a compiler.

Tony Huang · August 17, 2026

Software spent four decades building its safety net, one tool at a time. Version control gave every change an author, a reason and a history. Code review made a second pair of eyes routine instead of heroic. Type checkers made whole categories of mistake unwritable. Continuous integration made the verdict on a change arrive in minutes, on every commit, whether or not anyone remembered to ask for it.

Schematic design got none of it. A schematic today is still a drawing: symbols placed on a canvas, wires drawn by hand, correctness judged by looking. The mistakes that matter are structural — a regulator enable pin that was never wired, a polarized part connected backwards, a 5 V rail landing on a pin rated for 3.3 — and a drawing has no way to refuse them. They pass review, because review is a human looking at a picture, and pictures do not fail loudly. So they surface at the assembly house, or on the bench when the first board comes back and does not power up. The feedback loop is measured in respins, and every lap of it costs weeks.

I don't think the fix is a better canvas. I think the fix is to stop treating the schematic as a drawing at all.

A board is a program

CoHDL starts from a literal claim: a board is a program. Not like a program — a program. The schematic is plain text files. A net is a typed value: the 3.3 V rail is declared [3.3V], and the compiler holds you to it. Components come from versioned packages, pinned in a lock file by exact version and content hash. A mistake is a compile error that names the instance and the pin. A design change is a diff a colleague can review line by line. And the build is reproducible down to the byte: same source, same dependency set — same verdict, same reference designators, same netlist bytes, today and in a year.

Here is what that looks like, trimmed from the Raspberry Pi Pico 2 reference design that ships with the compiler — the real board, transcribed from its datasheet:

Every pin on every device carries a connection obligation. A required pin left unconnected is not a warning; it is an error, because silence is not a valid electrical state. If a pin is deliberately unconnected, you say so with nc, in the source, where a reviewer can see the decision. Delete mcu.ADC_AVDD — the MCU's ADC supply — from its net in that design, and cohdl check answers: 

error[E701]: required pin `Pico2::mcu.ADC_AVDD` is unresolved: add it to a `net` or explicitly mark it `nc`

12 |     inst mcu: raspberrypi_mcu::RP2350A_QFN60

1 error emitted

That is a schematic mistake caught the way a type error is caught: at the desk, seconds after it was made, with the exact location and the fix in the message. Not at the assembly house, three weeks and one respin later.

Strictness buys expressiveness

The design thesis behind the language is that strictness and expressiveness are not a trade-off — strictness is what buys expressiveness. Rust's real lesson was never the borrow checker; it was that pushing correctness into the type system, making illegal states unrepresentable, is what makes bold, generic, composable code safe to write. Convention does not scale. A compiler watching your back does.

Translated to hardware: wherever a mistake is structural, it belongs to the type system. Units never coerce — a bare number where a resistance is expected is a compile error naming the expected and the actual unit type, not a value that happens to parse. Pin obligations are checked exhaustively at final assembly. Devices satisfy traits, and a claimed trait the device cannot satisfy is refused at the impl, not discovered in layout. Even the lexer is opinionated: type a Unicode Ω where the language expects ohm and the diagnostic tells you exactly that, rather than failing with a generic parse error.

What remains for the design-rule check — the traditional catch-all — is deliberately small: exactly four rules. A net's voltage exceeding a pin's rating, a polarity mismatch, a net that needs a driver and has none, a net with more than one. Those are genuinely emergent properties of the whole graph, things no single line of source can be blamed for. Everything else has been pushed forward into types, and the rule engine is forbidden from growing a fifth structural rule — if a rule could have been a type error, the rule is a design smell in the language itself. The discipline matters because rule engines rot: a check that fires late is a check that gets ignored.

The payoff is the expressive half. Because the compiler refuses to guess, the language can afford to let you say a great deal in very little: thirteen key switches and their matrix diodes are two array declarations, a decoupling network is a function call, a device can be generic over its specs. None of that would be safe in a language that quietly tolerated a floating pin.

Why AI is the forcing function

A language a model can write is a language a compiler can check. That symmetry is the entire strategy. LLMs became genuinely productive at software for one reason: code is text, and compilers and tests grade it — mechanically, deterministically, at zero marginal cost. Schematic capture never crossed that line, because its source of truth lives inside GUI databases an AI can neither write fluently nor be graded against honestly.

So CoHDL is built around a loop: generate, check, repair. A model emits source; the compiler grades it; every diagnostic carries a stable error code and a precise span, and cohdl check --json hands the same diagnostics to a machine in structured form; the model repairs and tries again. The compiler is the oracle, not a reviewer's mood. When we ran this loop for the MVP acceptance demo, the model's first draft left an ESP32's chip-enable pin unwired; the type checker answered with the E701 naming that pin, the next attempt wired it through a pull-up, and the design landed clean as an importable KiCad netlist with an honest BOM. That transcript is what "AI-native" means here. It is not autocomplete over a canvas — it is a correctness signal precise enough that repair becomes a mechanical step, and the verdict is the same whether a human or a machine asks for it.

Proof

A manifesto is cheap, so here is the evidence. The language is governed, not improvised: a written constitution fixes the mission, the priority ladder and the hard constraints, and every feature exists because an RFC was accepted for it. Thirty-one RFCs are accepted, all thirty-one are implemented in the compiler, and where the implementation deviates from accepted text, the deviation is recorded in a compliance ledger rather than papered over. The language specification — the compiled statement of all of it — is published in full.

The language has shipped a product. OpenMicroKbd is a 13-key macropad — rotary encoder, analog joystick, capacitive touch pad, 21 addressable RGB LEDs, an STM32 over USB-C — whose entire schematic is 823 lines of CoHDL. The compiler checked the design and emitted the netlist, BOM, footprints and layout constraints; Quilter placed and routed 88 components from those constraints; the board came back from the fab and worked. The full story is in the case study.

And the parts are real. The package registry is live at registry.cohdl.org: versioned packages pinned by exact version and content hash, with pinouts and land patterns transcribed from datasheets. The generated passive part numbers are verified against the manufacturer's own datasheet service — a part that does not resolve is omitted, never asserted.

What happens next

Open source, soon. The compiler is real — everything above was produced by it — but it is not yet downloadable, and a language for boards is only worth trusting when anyone can run the whole toolchain and check the work. The documentation is up first, so the design can be judged on its merits before the release. If you want to know the moment the source is public, the waitlist gets exactly one email, and that is the email.

The schematic is source code. It always should have been.

CoHDL 0.7.1: Array Elements
in Helper Calls

An array element can be passed to an instance-typed helper just like a scalar instance. Its trait constraints, physical identity, and pin obligations follow it through the call.

Tony Huang · Published October 28, 2026

Compiler v0.7.1 was released on September 12, 2026. This post fills a gap in our release coverage.

Issue #41 exposed a gap in instance-array support: passing an indexed pin worked, but passing the whole element to a helper could fail. The 0.7.1 patch resolves an argument such as xs[0] to the actual instance, including when the helper takes impl Trait or an explicit trait-bound generic parameter.

The two calls produce separate nets. Neither argument loses its array index, and the result matches the netlist from equivalent explicitly declared scalar instances. The same helper calls also compose inside other functions and subdesigns.

Selectors are checked at the call site

An out-of-bounds index names the valid range. Passing a bare array, indexing a scalar instance, or using range/list fan-out as an instance argument is rejected: an instance parameter receives one element. Trait bounds, concrete device matching, and final pin obligations continue to be checked.

Regression coverage checks both supported parameter forms, nested calls, separate connectivity, and byte-identical netlists against explicit-instance equivalents. Thanks to ZhangHanDong for the reproduction and analysis that led to the fix.

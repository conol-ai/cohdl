# CLAUDE.md

CoHDL v2 — a compiler for the AI-native PCB schematic language. Rust, single crate. The compiler pipeline and emitters have **zero external dependencies** (a deliberate choice: byte-stable, reproducible output is a hard constraint, so everything — TOML lock file, S-expression netlist, diagnostics JSON — is hand-rolled and deterministic). One scoped exception per RFC-014/DR-020: the LSP layer (`src/lsp.rs`) depends on pinned `lsp-types` (+ its `serde`/`serde_json` requirements) for the protocol's message shapes only — the JSON-RPC transport loop stays hand-rolled, and nothing outside the LSP layer may use these crates.

The previous implementation is on the `legacy` branch. It is reference material only — v2 is a ground-up rebuild; do not port legacy code.

**Live deviation — arbitrary rotation angles.** `rotate ANGLE` (both `place` and `pad`) accepts ANY whole degree in `0..=359`, not RFC-020's closed `{0, 90, 180, 270}`. Directed by the board author; RFC-020's text (and its "not arbitrary-angle rotation" non-goal) is superseded pending an RFC. `360` and above stays an error — a full turn is `0`, and `rotate 450` is likelier a slip than a deliberate 90. The enabling piece is `src/trig.rs`: a checked-in fixed-point sine table (`tools/gen_trig.py`, scale 2^64, quadrant symmetry off 0..=90) plus a 256-bit-intermediate multiply. **Never use `f64::sin`/`cos` for placement geometry** — it resolves to the platform libm, whose last bit is not portable, and emitted coordinates are byte-stability-critical. The table is exact at the four cardinals, so every pre-deviation board still emits identical bytes (regression-tested against both examples). `emit::silk`/`emit::kicad_mod` do use `f64` for arc tessellation; that precedent deliberately does NOT extend to rotation.

**Distribution (no RFC — repository tooling, user-directed 2026-08-11).** Compiler releases are `vX.Y.Z` tags: `.github/workflows/release-cohdl.yml` gates on tag == `[package] version` + `cargo test`, builds `[profile.dist]` (stripped; `[profile.release]` keeps `debug = true` for local profiling) for five targets (mac arm64/x86_64, linux musl x86_64/aarch64 — static, one artifact per arch runs on every distro — and windows x86_64), and publishes `cohdl-vX.Y.Z-<target>.tar.gz` + `sha256sums.txt` to a GitHub release. `install.sh` (repo root, curl-pipe-sh) and `cohdl self-update` (`src/selfupdate.rs` — system curl per the RFC-030 precedent, system tar for the compressed archive since RFC-030's own hand-rolled tar is deliberately uncompressed, verification via `src/hash.rs`) consume that artifact contract; the three are ONE contract — change them together. Since v0.5.0 the two macOS binaries are Developer ID-signed (hardened runtime + secure timestamp, identity `4F93FJA939`) and notarized in the release workflow before packaging — the `APPLE_CERT_P12`/`APPLE_CERT_PASSWORD`/`APPLE_API_KEY_P8`/`APPLE_API_KEY_ID`/`APPLE_API_ISSUER` repo secrets; the p12 bundles its intermediate CA, the throwaway-keychain import needs a real p12 password (`security` rejects an empty-password MAC), a bare executable cannot be stapled so Gatekeeper checks the ticket online, and the notarize step gates on the literal `status: Accepted` line because notarytool can exit 0 on a non-Accepted verdict. Artifact names are untouched — the three-place contract below is unchanged. The VS Code extension's releases (`vscode-v*`) pass `--latest=false` so the repository's "latest" is always a compiler release. The repo is public; v0.3.0 (2026-08-17) is the first shipped compiler release, verified live end-to-end (one-liner install + `self-update --check`). The repository's v0.1.0/v0.2.0 releases predate the rebuild and carry old-scheme artifacts (unversioned names, linux-gnu, no `sha256sums.txt`) — compiler versions count up from 0.3.0, and `install.sh` probes each candidate release for this platform's contract asset before selecting it, so legacy (and still-uploading) releases are skipped, never chosen as the numeric maximum.

**Package API docs (no RFC — registry tooling, user-directed 2026-08-19; contract in `docs/apidocs.md`).** docs.rs-style per-version documentation on registry.cohdl.org: the REAL compiler extracts a deterministic `schema_version: 1` JSON (`cohdl docs` → `src/emit/docsjson.rs` — every named top-level declaration + impls + a `foreign` section inlining dependency-owned pads/footprints/devices the previews need; geometry as canonical `geom::mm` strings; silkscreen markers pre-expanded via the SAME `emit::silk::graphics` both geometry emitters consume; `World.intents` is the one additive resolver change). The document travels as a SIDECAR — `PUT /packages/{name}/{version}/docs`, owner-authenticated, ≤200 MB (200,000,000 bytes), re-uploadable — and must NEVER enter the published tar (the tar is the RFC-029 hash identity; RFC-030 line 47). `cohdl publish` uploads it best-effort after a successful publish (extraction needs a cleanly-checking package; failure warns and never fails the publish — publish itself stays compile-free); `cohdl docs --publish` is the backfill for already-published versions. Server: byte-preserved, content-addressed R2 sidecar objects selected through D1 `versions.api_docs_r2_key` (legacy fixed-key fallback; `api_docs_size` remains the presence/size flag), `GET /api/apidocs?pkg&version`, `api_docs` boolean on package-detail version rows. Through 16,000,000 bytes the Worker fully parses and projects part-search rows; larger compact canonical documents stream with fixed length and R2-verified SHA-256, and deliberately carry no search projection. The application cap is distinct from Cloudflare's plan-dependent request-body ceiling. UI: an **API** tab on the package page (`?view=api`, `item=`, `q=`, `kind=` search params) with an item explorer, auto-drawn schematic-symbol SVGs (side assignment from RFC-008 pin roles is a tooling-layer convention, not a language guarantee), and exact footprint SVG previews (authoring frame is y-down = SVG's; pad rotation renders as `rotate(-angle)`). API docs are fetched only when that tab or an item deep link is selected and released promptly after it is left. E12xx codes are reused, none added. Zero impact on every existing artifact/verdict is pinned by `tests/apidocs.rs`.

**Registry search (RFC-030/DR-036 amendment, user-directed 2026-08-24).** `cohdl search QUERY [--json]` is a project-free, login-free, read-only client of stable `GET /search`. QUERY is trimmed, 3+ Unicode scalar values, ≤128 UTF-8 bytes, and contains no control characters. The endpoint has separate package/part result families and per-family `has_more` — never total counts — with `kind=all|package|part`, `limit=1..50` (default 20), and `offset=0..10000` (default 0, applied independently). Only the most-recently-published version is searched. Part rows come from that version's package-local `pub part` API-doc `items`, NEVER private or `foreign` items; FQ ownership is re-derived from the uploading package, and fixed projection budgets bound hostile excess while preserving the raw sidecar. Search covers package/FQ/short name, device, intent, args, variant, and primary/alternate AVL fields within those bounds; re-upload replaces that version's rows. Each existing package's most-recent sidecar needs one `cohdl docs --publish` backfill after the search index lands. The browser's `/api/search` stays package-only and unchanged. Human and `--json` modes carry identical bounded rows; `--json` is the `/search` discovery shape, NOT RFC-010 diagnostics. No hits = exit 0; invalid query = exit 2; registry/protocol failure = E1204/exit 1.

**Native `.kicad_pcb` emission (no RFC — emitter tooling, user-directed 2026-08-25; contract in `docs/kicad_pcb.md`).** `build --emit kicad_pcb` writes `out/<name>.kicad_pcb` — a KiCad 10 board file (`(version 20260206)`, pad nets BY NAME, no net table) straight from the IR: placements verbatim (CoHDL's authoring frame IS KiCad's +y-down board frame — never copy the IPC emitter's y-negation), net-bound embedded footprints from the SAME shared derivation as `.kicad_mod` (`kicad_mod::pad_plans`/`body_graphics` — one derivation, two dialects, RFC-031's anti-drift shape), the RFC-020 outline on Edge.Cuts (winding-aware arc midpoints), deterministic sha256-derived uuids, and IPC-shelf/40mm-grid staging for unplaced parts. RFC-026 back side in KiCad's own on-disk encoding, pinned empirically against pcbnew-written boards: fp angle = R+180 in (−180,180], local y negated everywhere, F.*→B.*, `justify mirror`, pad-local rotation REVERSED, chamfer corners swap vertically — semantic parity verified live against pcbnew output for both examples and both OpenMicroKBD revisions (v1: 88 footprints / 33 bottom; v2: 140 / 53). `--emit` is now repeatable with distinct values (same value twice stays the F12.5 duplicate error). This retires the `tools/kicad_board.py`/pcbnew dependency (script kept for reference); a routed board is protected only while FOREIGN to `out/.cohdl-manifest` — route on a copy outside `out/`, never in place.

**Schematic explorer (no RFC — standalone tooling, merged from `feat/explorer` 2026-08-27; details in `explorer/README.md`).** `explorer/` is a read-only, live-reloading schematic projection of a checked design: a Rust extractor crate (`explorer/extractor/` — compiler pipeline → deterministic ExplorerModel JSON v1, plus a std-only hand-rolled HTTP + SSE `--serve` mode that binds loopback only) and a React/ELK frontend (`explorer/web/`). Like `registry/` and `editors/vscode/`, the extractor is a standalone crate OUTSIDE the compiler's zero-dependency rule (path-dep on `cohdl`, serde for JSON) with its own CI job; it is read-only against `cohdl.lock`/`design.lock` and resolves deps in the offline check/LSP shape (`ResolveOpts { skip_transitive: &[], fetch: None }`). Hot reload is two composed loops: the watcher re-extracts on `.cohdl`/`cohdl.toml` mtime change (~500 ms; parser error recovery keeps the full design with span-exact diagnostics riding in the model, and a hard extraction failure keeps the last-known-good model with a `live_error` overlay), and `npm run dev` (port 5198) proxies `/api` to the extractor (5199) for frontend HMR. AI writes ONLY the `views/<Design>.view.json` partition labels (`skills/view-gen/SKILL.md`) — a bad view file changes grouping, never topology. The explorer also ships as a signed+notarized+STAPLED universal macOS app (`CoHDL Explorer.app` in a DMG): `explorer-vX.Y.Z` tags (version = `extractor/Cargo.toml`) drive `.github/workflows/release-explorer.yml`, which reuses the compiler release's APPLE_* secrets and publishes `--latest=false` like the VS Code track; the bundle pieces live in `explorer/app/` (Info.plist with `LSUIElement`, icns from the brand icon, `make_dmg.sh`), and app mode is `src/app.rs` — triggered by the `.app/Contents/MacOS/` path with no argv, osascript folder picker, free-port serve, browser open, and an SSE-viewer idle exit (5 min after the last tab closes) so the Dock-less app never lingers.

**EasyEDA / LCEDA Pro netlist (no RFC — emitter tooling, user-directed 2026-08-27; contract in `docs/easyeda.md`).** `build --emit easyeda` writes `out/<name>.enet` — the Constitution's second named netlist target (LCEDA Pro JSON v2.0.0, **File → Import → Netlist**), whose MVP cut ("one faithful target is enough proof") is hereby superseded by the board author. A NETLIST, not a board: geometry stays with `kicad_pcb`/`ipc2581`, and all three `--emit` values compose. The byte shape is pinned against the v1 compiler's emitter (`legacy` branch, `crates/cohdl-codegen-lceda` — reference for the FORMAT only, per the no-porting rule): v1's top-level struct order, string-sorted object keys everywhere (v1's serde_json BTreeMap bytes), `gge<n>` Unique IDs counting up in designator natural order. Semantics are the `.net` re-projected through the SAME shared derivations (`kicad::principal_value`, footprint symbol fq path, `Device::pins_for` physical expansion — the two netlists cannot disagree; cross-checked in `tests/easyeda.rs`); multi-pad logical pins flatten to one `pinInfoMap` row per pad (the RFC-027 convention), `nc` pins are guaranteed-absent (DR-012), a pin-less mechanical part keeps an empty map, and every net gets a `designRule.netRule` row with the empty `TrackPhysics` binding. Hand-rolled JSON via `emit::json::json_str` — zero dependencies. A live LCEDA Pro import is the human checkpoint, as pcbnew is for `kicad_pcb`.

## Commands

- `cargo build` / `cargo test` — build and run all tests
- `cargo run -- check <file-or-dir> [--json]` — parse + resolve + type-check + residual DRC (RFC-010 `--json`)
- `cargo run -- build <file-or-dir> [--json] [--emit easyeda] [--emit ipc2581] [--emit kicad_pcb]` — check + emit KiCad `.net` + BOM CSV (+ `design.lock`; `--emit easyeda` adds the LCEDA Pro `.enet` netlist, `--emit ipc2581` the RFC-015 partner document, `--emit kicad_pcb` the native KiCad 10 board; `--emit` repeats with distinct values)
- `cargo run -- update <dir> [NAME|--dep NAME]` — re-resolve to the greatest published semantic version (registry first, local fallback), rewrite `[dependencies]` + `cohdl.lock` (RFC-029/030; also migrates a manifest with no `[dependencies]`)
- `cargo run -- add NAME[@X.Y.Z] <dir>` / `remove NAME <dir>` / `install <dir>` / `login` / `publish <dir>` — the RFC-030 registry verbs (COHDL_REGISTRY overrides registry.cohdl.org; COHDL_HOME overrides `~/.cohdl`)
- `cargo run -- search QUERY [--json]` — search registry packages + most-recently-published public parts; no project or login, bounded results with per-family `has_more`
- `cargo run -- docs <dir> [--out FILE] [--publish]` — emit the deterministic package API-docs JSON (docs/apidocs.md; feeds the registry's API explorer) to stdout/FILE, or upload it to the registry for the already-published version (`--publish` is the backfill path; `cohdl publish` uploads automatically)
- `cargo run -- self-update [--check]` — replace the running binary with the newest `vX.Y.Z` GitHub release (`--check` reports only); `cohdl --version` prints version + release target triple
- `cargo run -- fmt <file-or-dir> [--check]` — rewrite `.cohdl` into canonical form (RFC-009)
- `cargo run -- lsp` — the LSP server on stdio (RFC-014; editor setup in `docs/lsp.md`)
- `harness/` — the generate→check→repair demo harness (script, not product)
- `python3 tools/gen_passive.py` — regenerate `lib/passive/` (then `cargo run -- fmt lib/passive --check`); `python3 tools/verify_passive_mpns.py [--all]` re-checks the emitted part numbers against Yageo

## Architecture (pipeline = the verdict ladder)

`parses ⊂ resolves ⊂ type-checks ⊂ connects ⊂ passes residual DRC ⊂ emits netlist`

- `src/span.rs`, `src/diag.rs` — SourceMap, spans, diagnostics (every diagnostic: stable code + precise span; codes registry in `docs/error-codes.md`)
- `src/lex.rs`, `src/ast.rs`, `src/parse.rs` — hand-written lexer + recursive-descent parser (deterministic, no unbounded lookahead — Constitution hard constraint)
- `src/resolve.rs` — cross-file symbol table (project files + the manifest's exact dependency set)
- `src/check/` — the heart: units (RFC-001), impl satisfaction (RFC-003), generics (RFC-007), fn expansion with cycle detection (RFC-006), pin exhaustiveness at final assembly (RFC-002)
- `src/ir.rs` — flat post-expansion design IR (instances, nets, nc)
- `src/lock.rs` — design.lock + the pure-function designator allocator with checked injectivity postcondition (RFC-005)
- `src/drc.rs` — exactly four rules (RFC-004): voltage-exceed, polarity-mismatch, single-driver, multi-driver. **Never add a fifth structural rule** — that's a type-system job.
- `src/emit/` — KiCad `.net` (S-expr) + BOM CSV + `layout.json` (RFC-013) + IPC-2581 XML (RFC-015)
- `lib/` — the library root: bare package families live directly below it and manufacturer packages at `lib/@scope/name`; manifests drive discovery and no package needs a resolver code path of its own
  - `lib/std/` — core traits only: `TwoTerminal`, `Capacitor`, `Resistor`, `Polarized`, `Diode`, `IC`, and `Connector`. Because std is every package's implicit prelude, it must never accumulate devices, parts, pads, footprints, or domain-specific traits
  - `lib/passive/` — root namespace `passive::*`; chip resistors, MLCCs, chip inductors, their lands, and passive helper circuits. Resistor/MLCC source files are GENERATED by `tools/gen_passive.py` (never hand-edit a generated parts file). Yageo primary throughout: RC_L resistors and CC-series MLCCs, both part-number schemes derived from Yageo's own datasheets; Vishay CRCW alternates on resistors and real Samsung CL alternates on capacitors (`tools/passive_data/samsung_cl.json` — Samsung's thickness code is not derivable, so it is a table, not a rule). Which capacitors exist is datasheet data (`yageo_mlcc.json`), not a guess, and every emitted part number is checked against Yageo's specsheet endpoint by `tools/verify_passive_mpns.py` — a part that does not resolve is omitted, never asserted
  - `lib/usb/` — `usb::connectors::type_c::*`, `usb::connectors::micro_b::*`, and `usb::pd::ccg6df::*`; `lib/connectors/` — general connectors such as `connectors::headers::smd_254::*` and `connectors::headers::castellated_254::*`
  - `lib/esd/`, `lib/diode/`, `lib/flash/`, `lib/ldo/`, `lib/led/`, `lib/mic/`, `lib/mosfet/`, and `lib/osc/` expose component declarations at their package roots; reusable QFP/LQFP, BGA, CSP/WLCSP, and SOIC/TSSOP fabrication geometry lives in `lib/qfp/`, `lib/bga/`, `lib/csp/`, and `lib/soic/`
  - `lib/@ti/dcdc/` — `ti_dcdc::controllers::multiphase::*`; `lib/@st/stm32/` — the pinned-ST-source generated device catalog and source-joined exact parts at `st_stm32::*` (fabrication geometry is dependency-owned, never copied into this manufacturer package); `lib/@espressif/esp32/` — the pinned-Espressif-source generated ESP32-lineage device/part catalog at `espressif_esp32::*`, with vendor module geometry locally owned and reusable QFN geometry dependency-owned; `lib/@raspberrypi/mcu/` — `raspberrypi_mcu::*`; `lib/@richtek/dcdc/` — `richtek_dcdc::buck_boost::rt6150b::*`. Quoted scoped manifest names normalize to underscore package namespaces in CoHDL source
- `tests/` — fixture tests mapped 1:1 to the MVP exit criteria

## Non-negotiable invariants (from the Constitution / RFCs)

- Same source + same exact dependency set → same verdict, same designators, same netlist **bytes**. No HashMap iteration order leaking into output — use BTreeMap or explicit sorts everywhere output-adjacent.
- Zero unit coercion; a bare number where a unit is expected is a compile error naming expected vs. actual.
- Every diagnostic names the exact construct (instance, pin, trait, unit) — never a bare "type mismatch".
- The designator allocator asserts injectivity as a postcondition on every run.
- Unicode `Ω` / `°C` must produce a targeted "use `ohm` / use `C`" diagnostic, not a generic lex error.

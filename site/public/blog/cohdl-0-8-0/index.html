CoHDL 0.8.0: Parameterized
Circuit Construction

Channel counts, wiring loops, and placement grids can share typed compile-time values. CoHDL expands the result into ordinary instances and nets, then checks the resulting circuit.

Tony Huang · Published October 28, 2026

Compiler v0.8.0 was released on October 1, 2026. This post fills a gap in our release coverage.

A board family often changes one count in several places: the number of channels, the connections between them, and the positions on the PCB. CoHDL 0.8.0 lets those decisions share local constants and exact expressions, so changing the count does not require copying another set of wiring and placement statements.

Counts and distances have distinct types

Repeat construction with an explicit identity

Labelled for loops use half-open ranges: 0..N visits zero through N minus one. Circuit loops can connect pins, mark pins unconnected, call helper functions, and carry placement operations. Layout loops repeat placements. The label and iteration value form part of the identity of objects created through helpers, preserving existing designators when a loop grows. Renaming the label changes that identity.

Declare instance and subdesign arrays outside the loop. Direct instance or subdesign declarations in loop bodies are rejected, as are directly authored named nets. Declare a shared named rail outside the loop and join it through anonymous net _ connections. These rules make repeated connectivity explicit.

Reusable blocks and bounded evaluation

Functions and subdesigns can take const N: Int generic parameters, so a reusable block can own its channel count. Evaluation happens during compilation, with checked arithmetic and bounded expansion. No loop becomes firmware. Every expanded instance still participates in pin-obligation and residual DRC checks.

Formatter, LSP, editor grammars, Explorer extraction, and registry API documentation understand these constructs. The diagnostic JSON interface remains schema 1. Package API docs use schema 2 when the new constructs occur, retaining schema 1 for legacy documents; consumers of cohdl docs need to support both.

Implementation shipped; language proposal remains provisional

This release implements the proposed RFC-033 design. The proposal has not been promoted to an Accepted language decision. Its scope and implementation boundaries remain recorded in the compliance report.

CoHDL 0.8.1 subsequently fixes parser hangs on malformed input. Use the latest compiler for these features and their follow-up fixes.
